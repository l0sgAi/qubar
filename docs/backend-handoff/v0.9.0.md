## 3. 按功能的对接要点

### 3.1 用户关注（详见 `docs/api/follow-api.md`）

接口：

| 接口 | 登录 | 说明 |
|---|---|---|
| `POST /follow/:user_id` | 需要 | 关注，幂等；返回 `{relation}`（1 或 3） |
| `DELETE /follow/:user_id` | 需要 | 取关，幂等；返回 `{relation}`（0 或 2） |
| `GET /follow/stats/:user_id` | 可访客 | `{user_id, following_count, follower_count, relation, list_visible}` |
| `GET /follow/following/:user_id` | 可访客 | 关注列表，`?cursor=&size=`（默认 20，上限 50） |
| `GET /follow/followers/:user_id` | 可访客 | 粉丝列表，同上 |
| `GET /follow/mutual` | 需要 | 我的互关列表 |
| `POST /follow/relations` | 需要 | `{user_ids: [...]}`（≤ 100）→ `{relations: {id: 0..3}}` |
| `GET /user/settings` / `PUT /user/settings` | 需要 | `{follow_list_visibility: 0 公开 / 1 私密, dm_permission: 0–3}`，PUT 为部分更新（`dm_permission` 见 §3.5） |

`relation` 是**当前登录用户**与目标用户的关系：`0` 未关注 →「关注」；`1` 我关注了对方 →「已关注」；`2` 对方关注了我 →「回关」；`3` 互关 →「互相关注」。访客或看自己时恒为 `0`。

要点：

- 关注 / 取关后用响应里的 `relation` 直接更新按钮；计数需要变化时重新调 stats（或本地 ±1 后以 stats 为准）。
- 看自己的主页不显示关注按钮（接口会对关注自己返回 400 `Cannot follow yourself`）。
- 列表项结构 `{user: {id, username, avatar_url}, follow_time, relation}`；列表项的 `relation` 是**我**与该项用户的关系，不是列表主人与他的。
- 列表结束**只看 `has_more`**：服务端会过滤已禁用 / 删除的用户，一页可能少于 `size` 条甚至为空页。列表人数可能略少于计数，属预期。
- 游标不透明、原样回传；关注列表和粉丝列表的游标不能混用（400 `Invalid cursor`）。
- `list_visible = false`（对方设为私密，且我不是本人）：数字照常显示但不可点击；硬调列表会 403。
- 达到关注上限：400，`message` 形如 `following limit reached: you can follow at most 2000 users`，提示「关注人数已达上限」。
- 目标用户不存在 / 已禁用 / 已删除：stats 和关注都返回 404，主页按「用户不存在」处理。
- AI 机器人账号可以被关注，按钮逻辑与普通用户相同。

错误码对照：信封 `code` `201`=400、`202`=401、`203`=403、`204`=404、`208`=429、`500`。`message` 是英文，前端按 `code` 和场景渲染自己的文案。

### 3.2 被关注通知（详见 `docs/notice-frontend-api.md`）

- 新增 `notice_type = 12`：文案「{actor} 关注了你」；**没有** `post_id` / `comment_id` / `circle_id`，`snippet` 为空串，不要拼。
- 点击跳 `actor.id` 的用户主页，不要走帖子详情跳转逻辑。`actor` 缺失（关注者已注销 / 被禁用）时文案兜底「有人关注了你」且不可点击。
- `noticeDisplay.js`：`NOTICE_TEMPLATE_KEYS` 加 `12`；按 tab 过滤时 `type` 现在允许 1–12（例如可把 12 归到「互动」或单独的「关注」tab）。
- 同一关注者只有一条：对方取关后再关注，复用原通知并重新变为未读，列表位置不变。
- 可选：通知上直接显示「回关」按钮，关系用 `POST /follow/relations` 批量取（通知本身不带关系）。

### 3.3 首页关注 tab（详见 `docs/api/home-feed-api.md`）

- 接口与参数不变，只是内容变为「已加入圈子的帖子 ∪ 关注的用户发的帖子」。
- 只需改空态：两者都没有时返回空，文案改为引导「加入圈子或关注感兴趣的人」（`feed.emptyFollowing`）。
- 关注 / 取关后重新从第一页请求即按新关系返回。

### 3.4 帖子分享（详见 `docs/api/post-share-api.md`）

- 只做**外部分享**：前端拼链接 `https://<前端域名>/post/<post_id>`，复制链接或唤起系统分享（`navigator.share` 可用时），同时调 `POST /post/share {post_id}`。链接里不要带用户 ID 或 token。
- 响应 `{share_count, first_share}`：成功后用 `share_count` 覆盖本地显示，`is_shared` 置 `true`；`first_share=true` 时可播放 +1 动效。
- 接口失败不影响分享本身：401 时仍允许复制链接（只是不计数）；503（`code` 212，服务端已回滚）可直接重试；404 提示「内容不可分享」。
- 分享不可撤销，没有取消接口；`is_shared` 变为 `true` 后不会再变回。
- 字段返回范围：

| 接口 | `share_count` | `is_shared` |
|---|---|---|
| `GET /post/detail/:id` | ✅ | ✅（访客 `false`） |
| `GET /post/home`（4 个 tab）、`GET /trending`、`GET /discover` 的帖子项 | ✅ | ✅ |
| `GET /post/list`、`/post/my`、`/post/user/:user_id`、`/circle/posts`、`/collect/posts`、`/history/posts` | ✅ | —（与 `is_liked` 一样不返回） |

### 3.5 私信（详见 `docs/api/message-api.md`）

接口（全部需要登录）：

| 接口 | 说明 |
|---|---|
| `POST /message/send` | `{receiver_id, content, client_msg_id?}` → `MessageVO` + `remaining_count` |
| `GET /message/conversations` | 会话列表，按最后消息时间倒序；项：`conversation_id, type, peer_id, peer, last_message, unread_count` |
| `GET /message/conversations/with/:user_id` | 按对方查会话，`{conversation: … / null, can_send, cannot_send_reason}`；只读，不创建会话 |
| `GET /message/conversations/:conversation_id/messages` | 消息历史，**新 → 旧**返回（渲染时反转），`next_cursor` 往更旧翻；附 `last_read_message_id` |
| `POST /message/conversations/:conversation_id/read` | 清零该会话未读 |
| `DELETE /message/conversations/:conversation_id` | 只对自己隐藏；对方再发消息会重新出现，只显示删除之后的消息 |
| `GET /message/unread-count` | 私信未读总数 `{unread_count}` |

`MessageVO`：`id`（UUIDv7，越大越新）、`conversation_id`、`sender_id`（等于我即「我发的」）、`msg_type`（1 文本）、`content`、`create_time`。

页面与交互：

- **入口**：导航栏 / 移动端 TabBar 加私信入口，角标用私信未读总数（与消息中心角标**分开**）。
- **用户主页「私信」**：调 `conversations/with/:user_id`；`null` 时进入空白聊天页，发出第一条后用 `send` 响应里的 `conversation_id`。机器人账号主页不显示私信按钮（发送会 403 `This user cannot receive private messages`）。
- **会话列表**：`peer` 可能为 `null`（对方已禁用 / 删除），显示「已注销用户」且输入框禁用；`last_message.content` 只有前 100 字。
- **聊天页**：进入时拉第一页并调 `read`；上滑用 `next_cursor` 加载更旧消息；可用 `last_read_message_id`（在调 `read` 之前读取）画「以下为新消息」分隔线。`conversations/with` 在「我删除过、之后没有新消息」时返回的会话 `last_message` 为 `null`。
- **发送**：正文 1–2000 字符、不能全空白；每条新消息生成一个 `client_msg_id`（UUID），超时 / 网络错误 / 5xx 时用**同一个** `client_msg_id` 重试；本地按响应 `id` 去重。不同消息不要复用同一个键。
- **未关注 5 条限制**：`remaining_count` 为 `null` 表示不受限；为数字时可在输入框附近提示「对方关注你或回复前，还可发送 N 条」；`0` 表示下一条会被拒。403 `dm limit reached` 时提示「对方关注你或回复后可继续发送」。
- **私信权限设置（#240）**：
  - 设置项 `dm_permission`（`PUT /user/settings`）：`0` 所有人（默认）/ `1` 仅我关注的人 / `2` 仅互相关注 / `3` 关闭；非法值 400。
  - 进入用户主页 / 聊天页时看 `conversations/with/:user_id` 的 `can_send`：`false` 时置灰输入框，按 `cannot_send_reason` 提示，不要等发送失败才提示。
    枚举（只返回第一个命中的）：`recipient_not_found`「该用户不存在」、`recipient_unavailable`「该用户不接收私信」（机器人）、`following_only`「对方只接收其关注的人的私信」、
    `mutual_only`「对方只接收互相关注的人的私信」、`dm_closed`「对方已关闭私信」、`dm_limit_reached`「对方关注你或回复后可继续发送」。
  - `can_send` 计入了 5 条限制，但**不反映频率限制**；它是查询时刻的结果，最终以发送接口为准。
  - 发送被权限拒绝时返回 403，`message` 分别为 `This user only accepts private messages from people they follow` / `… from mutual follows` / `This user has turned off private messages`。
  - 用同一个 `client_msg_id` 重试已发出的消息时，即使对方之后改成拒收，仍返回原消息（200）。
- **频率限制**：429（`code` 208），`message` 说明是每分钟 / 每天 / 每天新会话哪一项，提示「发送太频繁，请稍后再试」，**不要自动重试**。
- **其他错误**：403 `Your account cannot send private messages`（自己账号被禁用）；404 `No such user`（对方不存在）；404 `No such conversation`（会话不存在或不是成员）。

### 3.6 SSE 实时推送（详见 `docs/notice-stream-frontend-api.md` §3.4、`docs/api/message-api.md` §3）

私信不单独建连接，复用 `useNoticeStream.js` 现有的 `/notice/stream` 连接，新增两个具名事件：

- `dm-unread`：`{unread_count}`，私信未读总数**全量**，首包紧跟 `unread-count` 下发；直接替换私信角标，不要自己 +1。
- `dm-message`：新私信摘要（只推给接收方）：`{id, conversation_id, sender_id, sender, msg_type, content, truncated, create_time}`，`content` 只有前 100 字。
  - 正在看该会话：`truncated=false` 直接追加到底部（按 `id` 去重），然后调 `read`；`truncated=true` 重新拉第一页。
  - 在会话列表页：把该会话顶到最前并更新摘要，或直接刷新列表。
  - 其他页面：可弹提示（`sender.username` + `content`）。
  - 不保证送达，也不会推送我在别的端发出的消息；重连后以拉取为准。
- SSE 不可用时现有轮询逻辑要同时轮询 `GET /message/unread-count`（与消息中心同为 30s）。
- 建议把私信未读数做成和 `unreadCount` 并列的独立 ref（如 `dmUnreadCount`）导出，供导航栏与私信页共用。

## 8. 联调环境说明

- 本地后端：后端仓库切 `develop`（或 v0.9.0 发版后的 `main`），`make dev-up && make dev-run`，地址 `http://localhost:8888`（与前端 `.env` 一致）。生产（`api.qubar.site`）要等发版 PR #275 合并并发布后才有这些接口。
- 开发栈**没有 CDC**：新建的帖子不会同步进 ES，所以首页各 tab、搜索、热门、发现页里看不到本地新发的帖子；关注 tab 的合并效果只能在生产验证。关注、私信、分享接口本身都走 PG / Redis，本地可以完整联调。
- 测试账号需要至少 3 个（A 关注 B、B 未关注 C 等），用于验证关系状态和私信 5 条限制；AI 机器人账号（`role = 2`）用于验证「不能私信」。
- 私信频率默认每分钟 20 条，联调时连续发送注意不要误触 429。
- 被关注通知约有 5 秒延迟（通知走批量消费）；SSE 未读数 1 秒内的多次变化会合并成一次推送，属正常。
